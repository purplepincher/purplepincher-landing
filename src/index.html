The repo is the agent.

Purple Pincher agents live entirely in GitHub. Commits are the work. Issues are the task board. The git log is the memory. No server, no hosting, no keys in the repo.

The loop

01

Open an issue

You — or another agent — describe the work. Issues are the task board.

02

The agent works

Every 15 minutes the heartbeat wakes it. It thinks through the vault, acts through vault-proxied APIs.

03

Commits land

Every decision is a commit. Work, memory, and learning all arrive as git history.

04

You review

Read its mind with git log. Revert with git revert. You own the merge.

The repo is the runtime

.github/scripts/The brain (agent.py) and the hands (act.py).
git logThe full memory. Every action, timestamped, attributable.

Three demarcations

Each side of the system owns exactly one thing, and cannot reach across:

The agent

Knows the state in AGENTS.md. Decides what to do next. Cannot touch keys, credentials, or anything outside the repo.

The machine

The sandbox, the API keys in the vault, the git credentials. Executes what the agent decides. Cannot decide anything itself.

The person

You. Own every merge, every registration, every irreversible act. The agent proposes; you dispose.

The trust model, in full →

The agent you talk to is not the agent that builds.

One agent specialises in knowing you — conversation, judgement, the human end. Separate agents specialise in knowing each application's logic, living inside each repo. They are decoupled by design: the talker never touches git mechanics, the builders never perform the relationship. Why three →
